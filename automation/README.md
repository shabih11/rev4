- المصدر: Google My Business عبر Windsor؛ ستة مواقع تربط بمعرفات ثابتة.
- الوجهة: `https://zcnfzrkegodvrtzimlnn.supabase.co/functions/v1/windsor-import`.
- ملف التشغيل: `.github/workflows/windsor-sync.yml`؛ موعده 22:00 بتوقيت الرياض، مع احتمال تأخير GitHub.
- الجدولة تعمل من الفرع الافتراضي فقط؛ يلزم اعتماد هذا الفرع قبل انتقال الجدولة إلى Supabase. رفع فرع Supabase يشغّل فحص تكامل أولي، والتشغيل اليدوي متاح أيضًا.

## الأسرار والهوية

يبقى `WINDSOR_API_KEY` في أسرار مستودع `shabih11/rev4` كما هو. لا حاجة إلى سر إدارة Supabase في GitHub؛ Edge Function يستخدم مفتاحه الإداري الداخلي بعد التحقق من توقيع GitHub OIDC وهوية المستودع والفرع وملف workflow والحدث والعمر والجمهور `rev4-windsor-supabase`.

لا يوجد مفتاح Windsor في المتصفح أو مستودع Git أو artifacts. لا تُطبع روابط المصدر ذات المفتاح ولا محتويات التقييمات في السجلات.

## السلوك

النافذة الافتراضية من 2026-08-01 إلى اليوم في الرياض، لالتقاط تصحيحات المصدر القديمة. يمكن ضبط `date_from` و`date_to` يدويًا. يُرفض الرد غير المكتمل، والموقع غير المعروف، والتقييم غير الصحيح، وتعارض معرفين قبل بدء الكتابة.

تُقرأ المعرفات الحالية على دفعات 100، وتُكتب التقييمات الجديدة أو المتغيرة فقط. لا حذف عند غياب صف من المصدر. لا كتابة عند تطابق المحتوى. تعيينات الموظفات الحالية تُحفظ تحت قفل صف قاعدة البيانات، ويُعاد ربط الوقت المصحح بالشفت المناسب. تتولى SQL تحديث المرآة ورقم إصدار البيانات.

بعض الدفعات قد تكتمل قبل فشل لاحق؛ إعادة التشغيل آمنة ومطلوبة لإكمال المزامنة. السجلات تعرض العدادات فقط.

نشر الوظيفة يتطلب نشر ملفات `supabase/functions/windsor-import/` إلى المشروع، مع `verify_jwt=false` لأن الوظيفة تتحقق من GitHub JWT بنفسها، وليس من رمز Supabase. لا تزل تحقق `verifyGithubToken`.
