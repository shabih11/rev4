# محاكاة حسابات الموظفات ومديرات الفروع

## الاستخدام

بعد تطبيق ترحيل قاعدة البيانات ونشر التطبيق، يظهر للمسؤول شريط «عرض كما تظهر للحساب». يختار حسابًا فعّالًا ثم يبدأ المحاكاة. يظهر اسم الحساب ودوره وفرعه واسم المسؤول الأصلي، مع التبديل المباشر أو العودة إلى المسؤول دون تسجيل خروج. زر تسجيل الخروج داخل واجهة الحساب المحاكى ينهي المحاكاة ويعيد المسؤول، ويحافظ على جلسة دخوله الأصلية.

المحاكاة للقراءة فقط دائمًا في هذا الإصدار. تعرض الميزات والبيانات المتاحة للحساب المستهدف، بما فيها إعدادات الميزات الحالية؛ لا تفتح ميزات معطلة للموظفة ولا تمنحها صلاحيات المسؤول. يبقى عرض المسؤول الأصلي متاحًا بالعودة إليه. لا تغيير لكلمات المرور ولا إصدار أو حفظ رموز دخول للموظفات.

## حدود الأمان والتسجيل

- جلسة Supabase الأصلية تبقى للمسؤول. سياق المحاكاة في الذاكرة فقط؛ إعادة تحميل الصفحة تعود للمسؤول. السجل غير المغلق ينتهي بعد 30 دقيقة، ولا يُفسّر انتهاء المدة على أنه خروج يدوي.
- كل سياق مرتبط بهوية المسؤول ومعرّف جلسة دخوله. كل قراءة تتحقق من الدور الإداري الحالي، وفعالية الحساب المستهدف وصلاحيته، والمدة وعدم إغلاق السياق.
- مسار `simulation_read` يعمل بصلاحية المستدعي `authenticated`، ويستخدم هوية الهدف مؤقتًا داخل طلب قاعدة البيانات ثم يستعيد هوية المسؤول، حتى عند الخطأ. يستعمل الدوال الحالية وقواعد RLS نفسها، دون مفاتيح خدمة أو تجاوز إضافي لقواعد القراءة.
- المسار يقبل قائمة ثابتة من القراءات فقط؛ لا أسماء دوال أو SQL ديناميكي من العميل. يرفض الحفظ والشراء وتغيير بيانات الدخول والحضور. طبقة الطلبات المشتركة تمنع كذلك التعديلات والاتصالات غير المصرح بها أثناء المحاكاة. لا يوجد خيار تفعيل الكتابة.
- تبقى هوية المسؤول أصلًا مخوّلة بأعمال الإدارة خارج مسار المحاكاة؛ هذه الميزة ليست وسيلة لسحب صلاحيات المسؤول أو تقييد أدواته الخارجية.
- جداول `private.admin_simulations` و`private.admin_simulation_reads` تحفظ البداية والنهاية وانتهاء المدة وهوية الطرفين واسم عملية القراءة فقط. ليست متاحة للموظفات ولا لعميل المتصفح. مراجعة السجل تتم عبر وصول تشغيلي مخوّل، دون نسخ بيانات الموظفات أو محتوى الطلبات إليه.
- التبديل يغلق السياق السابق. الطلبات المتأخرة من سياق آخر تُرفض في المتصفح، وتُعاد تهيئة حالة التطبيق عند التبديل والعودة. مفاتيح مخزن القراءة تضم هوية الحساب والدور والفرع.
- الحضور وعمليات الإنجازات والمشتريات لا تُرسل باسم الهدف. الموارد المشتركة فقط (الطقس وتوقيع روابط صور متجر الأفتارات، المتاحة أصلًا للأعضاء) تستعمل مساراتها المعتادة.

## حساب الإنتاج والموافقات

لم يُنشأ حساب ولم يُنشر التطبيق ولم يُطبق الترحيل على الإنتاج. يمكن اختبار الكود بحساب مسؤول موجود في بيئة معزولة. إنشاء الحساب الاختباري المخصص على الإنتاج يحتاج اعتماد هوية مالكه وطريقة تسليم دخوله وصلاحياته، ولا يستخدم كلمة مرور افتراضية أو بيانات دخول محفوظة بالمستودع.

قبل التفعيل: نجاح اختبارات SQL المعزولة في CI، مراجعة فرق الصلاحيات، اعتماد الترحيل والنشر وإنشاء الحساب كلٌّ بحسب نطاق الموافقة. يجب تحديد سياسة الاحتفاظ بسجل المحاكاة قبل الاستخدام التشغيلي؛ لا ينفذ هذا التغيير حذفًا تلقائيًا للسجل.

## التحقق

أضيف اختبار المتصفح المعزول `admin-simulation.spec.ts` واختبارات الطلبات `simulationFetch.test.mjs` واختبار SQL المعزول `admin_simulation.sql`، الذي يندرج تلقائيًا ضمن `npm run test:db` في CI. يشمل الهوية واستعادتها، وحظر الكتابة والحضور، والتبديل والإغلاق، ومنع الحسابات غير الإدارية والوصول عبر جلسة أخرى وتعطيل الهدف وانتهاء المدة.

تعذر تشغيل SQL محليًا لعدم وجود Docker؛ لا يُعتبر الترحيل معتمدًا للإنتاج قبل نجاحه في CI. اختبارات المتصفح تستخدم خدمات معزولة وبيانات اصطناعية وتحجب الاتصالات الخارجية، ولا تثبت وحدها صحة تنفيذ SQL.
