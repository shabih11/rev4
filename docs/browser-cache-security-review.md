# مراجعة فرق التخزين المحلي — 2026-10-20

## النطاق

مراجعة التغييرات الجديدة في `browserReadCache.ts` و`cloudSync.ts` و`dailyReadModel.ts` وربطها بـDataContext والصفحات. تغييرات المصادقة/القواعد القديمة غير المتعلقة بالمهمة ليست جزءًا من هذا الفرق ولا نُشرت هنا.

## التقييم

- المخاطر: مرتفعة عند اعتماد نسخة قديمة للحفظ، ومتوسطة عند التخزين المحلي وعزل الحسابات.
- يوجد مستهلك إنتاجي مباشر واحد لـuseCloudList في DataContext، ويوزع البيانات إلى صفحات الأدوار الثلاثة؛ أثر التغيير يشمل هذه الصفحات.
- يبقى مستند access مراقبًا من الخادم طوال الجلسة، ويعاد تحميل ملف الحساب عند تغير الصلاحيات. لا تعرض الجلسة قبل التحقق؛ حذف الصلاحيات يخفي الحساب ويمسح نطاقه المحلي، وتغير الدور أو الفرع يستبدل نطاق التخزين القديم. التخزين لا ينشئ دورًا أو جلسة بديلة.
- مفاتيح التخزين تتضمن UID ومعرّف الملف والدور والفرع، والاستعلام الفعلي والإصدار. المستخدم الجديد لا يعيد استخدام نطاق مستخدم آخر.
- بيانات users الخاصة في الذاكرة فقط. لا كلمات مرور أو رموز Auth في قاعدة التخزين الجديدة أو رسائل القياس؛ تخزين جلسة Firebase Auth يبقى تابعًا للـSDK القائم. ملفات تعريف العرض ومحتوى التقييمات تحفظ محليًا وفق طلب التخزين الدائم؛ صلاحيات العرض داخل التطبيق لا تحمي من شخص يملك أدوات المطور في الجهاز نفسه.
- تسجيل الخروج وتبديل الحساب بعد تحقق الجلسة الجديدة يمسحان نطاق الحساب السابق. لا تمسح البيانات عند إعادة التحميل العادية.
- معاملات Firestore تقرأ جميع المستندات الأساسية المتغيرة قبل الكتابة، وتقارنها بالنسخة التي بُني عليها التعديل. ظهور تعديل أحدث أو إلغاء الجلسة يمنع الكتابة. المرايا تكتب مع المستند الأساسي ضمن المعاملة نفسها.
- إبطال النتائج يقتصر على المجموعة المتغيرة والمرايا التي تغير محتواها؛ التعليق وحده لا يبطل ملخص الدرجات.
- الطلب الفاشل لا يخزن، والاستعلام الفارغ المكتمل يخزن. مهلة الاحتفاظ لا تعني مهلة السماح بالصلاحيات.
- BroadcastChannel يرسل بادئة إبطال محلية فقط؛ Web Locks يمنعان طلبين باردين متزامنين للمفتاح نفسه عند دعم المتصفح.
- فشل IndexedDB يعود إلى الذاكرة ويخفض ضمان البقاء بعد إعادة التحميل؛ لا يعطل التطبيق أو يسمح بالكتابة دون التحقق.

## التحقق والحدود

نجح 35 اختبارًا مركزًا للتخزين والمزامنة ونطاقات القراءة والملخص، بما فيها منع الكتابة القديمة، انتهاء الجلسة، عزل الأدوار، التنسيق بين تبويبين، حدود التخزين وفشله. نجاح lint/build. المتصفح المحلي أكد إعادة تحميل لوحة الترتيب والتقويم دون إعادة قراءة المجموعات المخزنة، وفتح قائمتي الفروع والموظفات دون قراءة جديدة.

لم يُختبر الحفظ ضد الإنتاج، أو رحلة دخول مستقلة لكل دور، أو قواعد Firestore بالمحاكي، ولم تُغيّر القواعد. لا يُدّعى غياب كل الثغرات خارج الفرق. الملخص الخادمي غائب حاليًا؛ دورة القراءة البديلة اليومية تبقى ضرورية إلى أن يجهز.

لا توجد ثغرة مؤكدة جديدة في نطاق الفرق تمت ملاحظتها. تظل قراءات التحقق، تغير إصدار البيانات، فشل التخزين/إخلاؤه وتسجيل الخروج أسبابًا مشروعة لإعادة الاتصال.
