# مشاركة سجلات الموظفات بين الفروع

2026-10-21، مقارنة مع `cdd320b`، وفق طلب المستخدم إتاحة بيانات الشفتات والتقييمات لجميع الأدوار والفروع.

## التغيير وحدود التفويض

- أزيل قيد حساب المشاهدة من نطاق قراءة التفاصيل في `recordFilters`، مع بقاء النطاق المطلوب وحد الثلاثين وعدم تحويل الطلب الفارغ إلى قراءة شاملة.
- `reviews_read` يجيز القراءة لكل عضوية نشطة. `timeline_read` يشارك أحداث الشفت فقط؛ الملاحظات ومرآة أحداث التقييم تبقيان ضمن الصلاحيات السابقة.
- لم تتغير سياسات INSERT/UPDATE/DELETE أو واجهات منح العضويات أو حسابات Auth. المستخدم غير المسجل والحساب بلا عضوية يظلان ممنوعين.
- تحديث إصدار `app_state` يبطل نتائج التفاصيل الفارغة المخزنة تحت السياسة السابقة، دون إلغاء التخزين أو تكرار القراءة عند التنقل.
- المطابقة بمعرف الموظفة فقط تمنع خلط الأسماء المتطابقة. تفاصيل الشفت تعرض التقييمات المرتبطة بمعرف الشفت، بما فيها ما بعد منتصف الليل، بدل تقييمات يوم الفرع كله.
- نافذة الفرع: الملخص أعلى، ثم الرسم، ثم أزرار الموظفات القابلة للوصول بلوحة المفاتيح والتي تفتح نافذة السجل القائمة.

## مراجعة الفرق

النطاق حساس لوجود توسعة قراءة مقصودة. مرجع blame للقيد السابق `a8a78751`؛ كان قيد القراءة تابعًا لحساب المشاهدة، فأعاد شفتات المشاهدة بدلاً من الموظفة المختارة. لـ `recordFilters` مستدعٍ مباشر واحد في `supabaseRecords`، ويستخدمه `useCloudList` في سبعة مواقع في DataContext؛ ثلاثة منها معطلة كمسارات قديمة. نافذة EmployeeCard مستخدمة في لوحة الترتيب، وتظل الطلبات حسب التبويب المفتوح.

سيناريوهات الفحص: موظفة ومديرة في فرع تحاولان قراءة موظفة بفرع آخر؛ ثم تعديل الشفت أو التقييم هناك؛ ثم قراءة ملاحظة خاصة أو حسابات الدخول. نجحت القراءة الجديدة، وبقيت التعديلات غير المصرح بها وقراءة الملاحظات والحسابات مرفوضة. العضوية المعطلة تعطي account_role فارغًا، فلا يجيز الشرط الجديد قراءتها. لم يظهر مسار تصعيد صلاحيات ضمن الفرق المراجع.

## الأدلة والحدود

- نجح lint والبناء واختبارات Node الـ27، مع تحذيري Fast Refresh السابقين.
- نجح `supabase/tests/shared_records.sql` داخل معاملة تُلغى: قراءة عبر الفروع، نطاق الموظفة المطلوبة، منع الكتابة، حماية الملاحظات والحسابات، ومنع المجهول وغير العضو.
- نجح ملف SQL الأمني السابق مع الاختبار الجديد؛ عُدلت حالة «اليوم السابق» لتقبل شفتًا حقيقيًا مستوردًا من اليوم السابق مع استمرار رفض نسبتها لشفت الاختبار الخاطئ.
- لا اعتماد على حسابات موظفات حقيقية لاختبارات المتصفح، ولم تُنفذ رحلة متصفح مسجلة في هذه المهمة. مراجعة ترتيب العناصر والربط كانت من الفرق والبناء.
- هذه مراجعة للفرق المحدد وليست تدقيقًا أمنيًا شاملًا. لا توجد مفاتيح أو أسماء أو حسابات حقيقية في التوثيق أو fixtures.
