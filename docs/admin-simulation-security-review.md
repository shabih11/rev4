خطر التغيير مرتفع بطبيعته لأنه يمس الهوية والصلاحيات ومسار الطلبات المشترك. عدم تسجيل ثغرة مؤكدة لا يثبت سلامة الترحيل غير المشغّل. توجد فجوة تحقق واحدة مانعة لاعتماد الإنتاج: غياب تشغيل SQL محليًا لعدم توفر Docker. لا توجد موافقة أو عملية نشر أو إنشاء حساب ضمن هذا التغيير.

## النطاق والسياق

المراجعة للتغييرات المحلية الخاصة بهذه المهمة فقط، مقابل HEAD؛ لم تُنشأ التزامات. المشروع متوسط الحجم (115 ملف TypeScript/React عند الفحص). استُخدمت مراجعة مركزة لمسار الهوية والطلبات والقراءة والتسجيل واعتماداته المباشرة. تغييرات الصور والشارات وإعداداتها التابعة لعمل متزامن مستبعدة.

التاريخ ذو الصلة: `b43095a` وضع عميل Supabase ومسارات RLS الحالية، و`a640e15` أضاف وصول العرض فقط، و`83cd289` عالج إعادة محاولة الكتابات القديمة. تمت مراجعة blame في `supabase.ts` وحارس الكتابة في `cloudSync.ts`. الحارس الجديد يضيف منع المحاكاة دون إزالة حارس viewer أو فحوص جاهزية البيانات أو معالجة تعارض الحفظ.

## التغيير ومدى الأثر

- `simulationState.ts`: سياق ذاكرة بلا كلمات مرور أو رموز دخول للهدف.
- `simulationFetch.ts` و`supabase.ts`: تحويل قراءات المحاكاة إلى قائمة محددة على الخادم، منع التعديلات والطلبات غير المعتمدة، إسقاط الردود بعد تغيير الهوية.
- `SessionApp.tsx` و`main.tsx`: إعادة تركيب البيانات والواجهة عند كل تبديل، لمنع تسرب الحالة المحلية بين الأدوار.
- `SimulationBar.tsx` و`App.tsx`: اختيار هدف فعّال والتبديل والخروج من المحاكاة.
- `AuthProvider.tsx`: منع دخول أو إعداد حساب آخر أثناء المحاكاة؛ زر الخروج يعيد المسؤول بدل حذف جلسته المحلية.
- `cloudSync.ts` و`usePagePresence.ts`: منع الكتابة والحضور باسم الهدف.
- الترحيل `20261110170656_admin_readonly_simulation.sql`: سجل خاص ودوال تحكم ومسار قراءة محدود يعمل بصفة SECURITY INVOKER.

وجد البحث 23 ملفًا يستورد عميل Supabase مباشرة؛ تغيير النقل مشترك بينها كلها. وُجد مستهلك واحد لـuseCloudSession/useCloudList خارج ملف التعريف (DataProvider). فُحصت مسارات RPC والكتابة المباشرة والوظائف الطرفية والتخزين، مع إبقاء الموارد المشتركة للطقس وصور الأفتارات متاحة.

## نموذج الهجوم والضمانات المفحوصة

1. مستخدم مجهول أو موظفة تحاول بدء المحاكاة أو استدعاء القراءة: دوال الخادم تتطلب عضوية admin حالية؛ يمنع التنفيذ عن anon.
2. استخدام معرّف سياق مسروق في جلسة أو حساب آخر: تحقق actor وsession_id مع كل قراءة؛ الانتهاء والإغلاق والتعطيل وتغير دور الهدف تمنع الوصول.
3. تمرير اسم دالة كتابة أو إدخال SQL ضمن operation/args: قائمة ثابتة وعبارات SQL ثابتة؛ لا تنفيذ ديناميكي ولا مسار كتابة لبيانات الأعمال.
4. استمرار هوية الهدف بعد فشل القراءة: استعادة claims وsub في النجاح ومعالج الاستثناء؛ اختبار SQL يراجع الهوية بعد القراءة.
5. تسرب بيانات الإدارة عبر طلب متأخر: مقارنة سياق الطلب الحالي قبل قبول الرد؛ إعادة تركيب واجهة البيانات، ومفاتيح مخزن منفصلة حسب هوية الحساب والدور والفرع.
6. اعتبار المحاكاة نشاطًا أو حضورًا للموظفة: إيقاف hook الحضور، وحظر RPC الحضور في النقل وقائمة الخادم؛ حفظ سجلات المحاكاة بجداول private مستقلة.
7. فقد جلسة المسؤول عند الضغط على خروج داخل واجهة الموظفة: عولج في AuthProvider قبل استدعاء signOut المحلي، ويغطيه اختبار المتصفح.

## حدود الثقة

رمز المسؤول الأصلي يبقى رمز مسؤول؛ التغيير لا يسحب صلاحياته خارج مسار المحاكاة ولا يحمي من مسؤول خبيث يستخدم أدوات أخرى. منع الكتابة على الخادم خاص بواجهة simulation_read التي لا توفر أوامر تعديل؛ الحماية المشتركة في التطبيق تمنع إرسال بقية أوامر الأعمال أثناء العرض المحاكى. لا تخفيف لـRLS ولا استعمال service_role في المتصفح.

الجداول الخاصة غير مقروءة من authenticated، ولا تحفظ أسماء أو بريدًا أو محتويات الطلبات. يحتفظ سجل البداية والنهاية بمعرّفات الطرفين والجلسة. تحتاج مدة الاحتفاظ إلى اعتماد تشغيلي؛ لا حذف تلقائي أو تنظيف إنتاج ضمن المهمة.

## الاختبارات والقيود

- `npm run verify`: نجاح lint والاختبارات (247) والبناء بعد تعديل الدخول؛ بقي تنبيه hook موجود سابقًا في DataProvider خارج نطاق المهمة.
- `tests/simulationFetch.test.mjs`: منع أوامر الأعمال والحضور، حفظ رمز المسؤول، pagination، الرد المفرد، إسقاط الرد المتأخر وعدم التحول إلى قراءة إدارية عند الرفض.
- `tests/browser/admin-simulation.spec.ts`: دخول فعلي مع خدمة معزولة، موظفة ثم مديرة ثم عودة، حظر كتابة عبر العميل المشترك، عدم إرسال حضور، والخروج من العرض مع إبقاء المسؤول مسجلًا.
- اختبارات `critical-flows` و`account-navigation`: تحمي الدخول والخروج والحفظ والتنقل للأدوار الثلاثة.
- `supabase/tests/admin_simulation.sql`: معاملة BEGIN/ROLLBACK ببيانات اصطناعية، الهوية والصلاحيات والرفض والعزل والمدة والتعطيل والسجل والحضور. مضافة للمسار التلقائي في CI، **لم تُشغّل** محليًا: `spawnSync docker ENOENT`.

لا ادعاء بتشغيل advisors أو فحص قاعدة الإنتاج أو تحقق SQL أثناء التشغيل. يجب نجاح اختبار SQL ومراجعة فرق النشر قبل اعتماد التفعيل.
