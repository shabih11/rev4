# اختبارات المشروع

المتطلبات العامة: Node.js 24 ثم `npm ci`.

## الفحص اليومي

`npm run verify` يشغّل lint واختبارات Node وبناء TypeScript/Vite مرة واحدة. لتغيير منطق محدود يمكن تشغيل ملف الاختبار المعني أولًا: `node --test tests/dataActions.test.mjs`.

تستخدم اختبارات المكتبات أداة تحميل مشتركة في `tests/helpers/typescript.mjs` بدل تكرار محوّل TypeScript في كل ملف. بعض الاختبارات القديمة التي تحتاج محاكاة خاصة لم تُنقل بعد. اختبارات المتصفح تكمل اختبارات المنطق ولا تحل محلها.

## المتصفح

```sh
npx playwright install chromium
npm run test:browser
```

يمكن استخدام Chrome المثبت محليًا عبر `PLAYWRIGHT_CHANNEL=chrome npm run test:browser`. يشغّل Playwright خادم Vite مستقلًا على `127.0.0.1:4173`؛ يجب أن يكون المنفذ متاحًا.

تُختبر رحلة الدخول والخروج للأدوار الثلاثة، ورفض الحساب غير المخوّل وكلمة المرور غير الصحيحة، وإنشاء الشفت وإعادة قراءته وتعديل موظفاته ورفض الحفظ المتعارض. تعمل المكوّنات والمزوّدات الفعلية، وتُحاكى استجابات الخدمة ببيانات مصطنعة مع منع أي اتصال بإنتاج Supabase. وقت المتصفح ثابت لأجل الاختبار فقط؛ لا تتغير ساعة التطبيق المنشور. ملفات traces عند الفشل في `test-results/` المستبعد من Git.

## قاعدة البيانات المعزولة

يتطلب هذا الفحص Docker يعمل محليًا. تستخدم إعدادات `supabase/config.toml` مشروع الاختبار المحلي `rev4-tests`؛ لا تنفّذ `supabase link` لهذا الغرض.

```sh
npx --yes supabase@3.0.0 start -x studio,imgproxy,edge-runtime,logflare,vector,supavisor,mailpit
npm run test:db
npx --yes supabase@3.0.0 stop --no-backup
```

تُطبّق هجرات المستودع على القاعدة الجديدة، ثم تُنفّذ ملفات `supabase/tests/*.sql` مع إيقاف التنفيذ عند أول خطأ. كل ملف يستخدم `BEGIN / ROLLBACK`، ويُجهّز داخله إعداد كلمة مرور مصطنع في Vault ثم يُلغى معه؛ لا تُقرأ إعدادات الإنتاج. لا يقبل المشغّل عنوان اتصال أو مفاتيح إنتاج؛ يستهدف الحاوية المحلية `supabase_db_rev4-tests` فقط. أمر الإيقاف أعلاه يحذف بيانات بيئة الاختبار المحلية.

يُواءم المشغّل تواريخ الأربعاء/الخميس/الجمعة في `security.sql` مع الشهر المفتوح مع الحفاظ على الأيام المتتالية وحدود التوقيت، حتى لا يفشل فحص مديرة الفرع لمجرد انتقال الشهر. تواريخ الاختبار غير الصالحة وطوابع الدخول تبقى كما هي. اختبار الطلبات يستخدم تقييمًا بعد افتتاح الجمعة عند تشغيله يوم الجمعة. لا تتغير قواعد إغلاق الأشهر أو الصلاحيات في التطبيق.

## GitHub Actions

ملف `.github/workflows/verify.yml` مشترك بين فحوص الفروع وطلبات الدمج ونشر Pages. يشغّل فحوص التطبيق وقاعدة البيانات في مهمتين مستقلتين؛ ينتظر النشر نجاحهما معًا. أول تشغيل قد يستغرق أطول لتنزيل Chromium وصور Supabase.
