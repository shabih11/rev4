# التحقق والإصدار

1. احفظ التعديلات المحلية غير المتعلقة بالمهمة دون ضمها إلى الالتزام. الهدف الافتراضي `main` وفق `AGENTS.md`؛ يُستخدم فرع آخر عند طلبه صراحةً.
2. شغّل `npm run verify` لفحص lint واختبارات Node وبناء الإنتاج. شغّل `npm run test:browser` لتغييرات المسارات الحرجة.
3. لتغييرات SQL والصلاحيات، شغّل بيئة الاختبار المحلية ثم `npm run test:db` كما في [دليل الاختبارات](testing.md). الاختبارات بمعاملات تُلغى؛ لا تستهدف الإنتاج.
4. راجع الفرق، وحدّث `main` من المستودع البعيد قبل الرفع. لا تستخدم force push ولا تضم أسرارًا أو بيانات استيراد خاصة.
5. يستخدم فحص الفروع وطلبات الدمج ومسار Pages ملف التحقق المشترك `.github/workflows/verify.yml`: lint، اختبارات Node، اختبارات Chromium، البناء، واختبارات SQL على Supabase معزول.
6. الرفع إلى `main` يشغّل Pages. لا يبدأ النشر إلا بعد نجاح فحص التطبيق وقاعدة الاختبار كليهما. المتصفح في الاختبارات يستخدم خدمة مصطنعة لا تتصل بـSupabase الحقيقي.
7. تحقّق من نتيجة GitHub Actions بعد الرفع؛ نجاح الفحوص المحلية لا يثبت نجاح النشر. نشر Pages لا ينشر هجرات Supabase أو Edge Functions تلقائيًا.

تفاصيل قاعدة البيانات: [عمليات Supabase](supabase-operations.md). مراجع Firebase في `docs/archive/` تاريخية.
