# متجر الأفاتار والمقارنة اليومية

## السلوك

- تُحسب زيادة الرصيد والتقدم في الترتيب من بيانات الشهر الحالية ومقارنتها مع نهاية أمس بالرياض. تُستخدم اللقطة اليومية المحفوظة عند توفرها؛ وفي غيابها يعاد حساب نهاية أمس من تواريخ التقييمات الحالية مع الإضافات اليدوية الحالية.
- لا يمكن إعادة بناء تغيير ربط تقييم قديم أو تعديل يدوي حدث قبل توفر أي لقطة؛ السجلات الحالية لا تتضمن وقت تغيّر الترتيب. لا تُضاف علامات تقدم غير مؤكدة لتغطية ذلك.
- تظهر زيادة الرصيد الموجبة بجانب الرصيد، ويظهر سهم بعدد المراكز المكتسبة مع أسماء الموظفات اللاتي جرى تجاوزهن. التعادل يتبع ترتيب الأسماء والمعرفات المستخدم في لوحة الترتيب.
- الجواهر متعددة الأوجه بالفضي والذهبي مع لمعة خفيفة تراعي تقليل الحركة. خلفية الترتيب هندسة هادئة وعمارة متدرجة، وتبقى لوحات البيانات بيضاء.

## المتجر

- تستبدل الإكسسوارات السابقة بأفاتارات كاملة. لكل مجموعة اسم وسعر مشترك لأشكالها، وتضيف الإدارة صور الأشكال وتسمياتها وتتحكم بعرضها. كل عملية اقتناء تشتري شكلًا واحدًا بالسعر المعروض؛ لا توجد رسوم إضافية لفتح المجموعة.
- كل شكل نسخة واحدة عالميًا. يُعرض اسم الموظفة المالكة، ولا يُعاد بيعه. يمكن للموظفة الاحتفاظ بعدة أشكال والاختيار بينها أو الرجوع للأفاتار الافتراضي.
- رصيد الشراء مستقل وتراكمي: حصّة الموظفة في جميع التقييمات الإيجابية المرتبطة بها حتى الآن، مطروحًا منها أسعار مشترياتها، بدقة منزلتين. لا تتغير نقاطها أو رصيد ترتيبها عند الشراء. تصحيح التقييمات أو ارتباطاتها قد يصحح المكتسب؛ لا تلغى المشتريات السابقة، ويكون المتاح بحد أدنى صفرًا.
- المتجر متاح لكل موظفة عند تفعيل مفتاحه، ولا يتطلب الفئة الفضية أو الذهبية. لم تُنشأ منتجات أو صور افتراضية داخل قاعدة البيانات؛ الإدارة ترفع المحتوى المعتمد.

## الحماية والتزامن

- الجداول الأربعة محمية بـ RLS. القراءة للأعضاء النشطين، والكتابة من وظائف محددة تتحقق من الدور والملكية والمدخلات. لا يمكن تمرير هوية مشترية بديلة من المتصفح.
- تنفذ الملكية والخصم والاختيار في معاملة واحدة. القفل ينسق مع عمليات الحفظ والدمج، والمفتاح الأساسي للشكل يمنع تعدد المالكين. تغير السعر يرفض الشراء حتى تحديث المعروض. الرصيد يُتحقق منه في الخادم.
- صور المتجر في مخزن Storage خاص `avatar-store`؛ التوقيع متاح للأعضاء النشطين، والرفع للإدارة العامة فقط. لا توجد سياسة استبدال. حذف صورة مستخدمة في الكتالوج ممنوع؛ يمكن حذف الرفع غير المرتبط بعد فشل الحفظ.
- يقبل العميل PNG وJPEG وWebP حتى ٥ ميغابايت و٤٠٩٦ بكسل لكل بعد. يعيد فك الصورة وترميزها إلى WebP مع تصغير البعد الأكبر إلى ١٢٠٠ بكسل. المسارات UUID ولا تتضمن اسم الملف الأصلي. لا يُقبل SVG أو روابط خارجية.
- تنقل عملية دمج الموظفات المشتريات إلى الحساب الأساسي مع الحفاظ على اختياره الحالي. حذف ملف ذي مشتريات محمي لمنع تحرير الملكيات أو فقدانها.

## التطبيق والتحقق

طُبقت `supabase/migrations/20261024184127_avatar_store.sql` على الإنتاج بإذن صريح، وتلتها هجرة `20261024184312_avatar_store_legacy_clients.sql` لضمان عمل الصفحات المفتوحة بالنسخة السابقة أثناء النشر. تضيف الجداول والمخزن والسياسات والوظائف وتحدّث الدمج وملخص الميزات، وتوقف الكتابة عبر واجهة الإكسسوارات السابقة دون حذف بياناتها.

التحقق المطلوب قبل النشر: lint والبناء واختبارات Node، ثم `supabase/tests/security.sql` و`supabase/tests/avatar-store.sql` في معاملتيهما المتراجعتين. اختبارات SQL تستخدم فروعًا وملفات وتقييمات مؤقتة معزولة. معاينة التصميم المعزولة لا تعوض اختبار رحلة رفع وشراء فعلية بحساب اختبار مأذون بعد تطبيق الخادم.

نجحت اختبارات الصلاحيات والمتجر على الإنتاج بمعاملات متراجعة، ولم تتبق ملفات أو فروع أو كائنات اختبار. يختبر ملف المتجر شرط سياسة منع حذف الصور المشار إليها دون حذف SQL مباشر، لأن Supabase يفرض استخدام Storage API للحذف. نجحت اختبارات Node الـ٤٢ والبناء وlint، وتمت معاينة التصميم المعزولة على الجوال والحاسوب دون تجاوز عرض الشاشة. لم تُنفذ رحلة رفع وشراء من متصفح بحساب اختبار فعلي.
