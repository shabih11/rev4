# مراجعة تغيير مزامنة Windsor — 2026-10-19

## النتيجة

المخاطر المتبقية: متوسطة بسبب اتصال خارجي وصلاحيات كتابة بيانات الإنتاج.
لا توجد ثغرات حرجة أو عالية معروفة في الفرق الذي روجع. تم التحقق من أول تشغيل كامل على GitHub بعد إضافة سر Windsor.

## النطاق والسياق

المرجع المنشور `a8a7875`؛ النسخة المحلية `ce3fcca` نقلت المصادقة والقراءة إلى Supabase. اختار المستخدم Firestore صراحةً، فاستعيد مساره محليًا. النسخة المنشورة كانت تستخدم Firebase بالفعل؛ لا تُنقل إليها تغييرات ترحيل Supabase أو تغييرات فرض كلمة المرور المحلية غير المتعلقة بالمزامنة.

شملت المراجعة: عامل المزامنة، نموذج تطبيع التقييمات المشترك، الاختبارات، ملف Actions، إزالة مؤقت Windsor ومتطلب تحميل السجل كاملًا المرتبط به، وروابط الحالة في لوحة الإدارة.
استخدم سجل Git وblame لتحديد أن استبدال Firebase Auth جاء في `ce3fcca`، وأن خط أساس القراءة المحدودة منشور في `a8a7875`.

## حدود الانتشار

- `useAuth`: سبعة مستهلكين في الصفحات والمكونات؛ لا تغيير في واجهته العامة.
- `fetchAndProcessWindsorReviews`: استدعاء يدوي واحد في لوحة الإدارة؛ أزيل الاستدعاء الدوري.
- عامل المزامنة: مستدعٍ إنتاجي واحد، GitHub Actions؛ تحديث ثلاث مجموعات ونقاط تحقق شهرية.
- تطبيع Windsor مشترك بين الاستيراد اليدوي والعامل، مع بقاء واجهة TypeScript.

## سيناريوهات الهجوم والفشل

- محاولة تشغيل OIDC من fork أو فرع آخر: شروط المزود تتحقق من معرّفي المالك والمستودع الرقميين، الفرع، ومسار ملف workflow.
- كشف المفتاح عبر فشل الشبكة: رسائل Windsor لا تحتوي على رابط الطلب أو الاستجابة الخام؛ يغطيها اختبار.
- رد مصدر فارغ أو غير صالح: لا حذف ولا تقدم لنقطة التحقق؛ تُتحقق المواقع والنجوم والتواريخ قبل الكتابة.
- مراجعة مكررة متعارضة أو تغيير فرع سجل قائم: رفض صريح بدل إعادة ربط موظفات فرع آخر.
- تعديل إداري متزامن: شروط updateTime/exists تمنع تجاوز التعديل داخل الدفعة؛ تبقى نقطة التحقق بعد الدفعات فقط.
- انقطاع أثناء المزامنة: الدفعات ذرية، وإعادة المحاولة تقارن المحتوى وتحافظ على تعيين الموظفات الموجود.
- قواعد Firestore لم تُضعف ولم تُنشر. صلاحيات IAM لحساب الخدمة لا تشمل الحذف، لكنها تعمل على مستوى قاعدة البيانات، وهو قيد يجب الحفاظ عليه عند صيانة العامل.
