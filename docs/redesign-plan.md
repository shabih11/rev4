# خطة إعادة تصميم rev4

الفرع المستهدف: `codex/supabase-production`.

## الهدف
واجهة عربية لإدارة السمعة والشفتات وقراءة نتائج الموظفات. الحفاظ على الوظائف والصلاحيات والطلبات الحالية، مع تحسين التسلسل البصري وقابلية الاستخدام على الهاتف.

## الاتجاه البصري
- هوية زرقاء مرتبطة بالعلامة الحالية: أزرق `#2459E0`، كحلي `#142B54`، خلفية `#F4F7FC`، سطح `#FFFFFF`، نص ثانوي `#65738B`، أخضر نجاح `#18765C`.
- خط Alexandria الموجود بالمشروع، بأوزان 400 و500 و600 و700 فقط، مع خط نظام احتياطي.
- الميزة البصرية المميزة: علامة نجمة صغيرة داخل مربع أزرق، وتكوين مداري ثابت في صفحة الدخول يوحي بأن التقييمات تتمحور حول الفريق. بقية الشاشات هادئة وظيفية.
- زوايا 12px للحقول، 20px للمجموعات، 28px للألواح الكبرى؛ ظلال خفيفة على اللوح الرئيسي فقط.
- تباعد 4/8/12/16/24/32/48، وقراءة RTL بمحاذاة يمين. الأرقام بوضوح مع tabular-nums.

## خريطة الشاشات
1. الدخول: شاشة مقسومة على الحاسوب؛ هوية وتعريف يميناً ونموذج واضح يساراً. هاتف بعمود واحد.
2. الإدارة العامة: شريط جانبي يميناً، تصفية فرع واضحة، محتوى قابل للمسح البصري، حالات التنقل موحدة.
3. مديرة الفرع: رأس هادئ، تقويم الشفتات واضح، وأزرار حفظ/إلغاء ثابتة المعنى.
4. الموظفة: تحية، نتيجة شهرية مميزة، مؤشرات تفصيلية، سجلات قابلة للفتح عند الطلب.
5. لوحة الترتيب: الحفاظ على العرض التفاعلي والبطاقات الحالية مع توحيد الهوية وتخفيف الزخارف.
6. الملف الشخصي والنوافذ: نفس الحقول والأزرار والتباعد وحالات الخطأ والتحميل والفراغ.

## خطة التنفيذ
1. مراجعة الشاشات الحالية وحفظ البرومبت المستقل.
2. تنفيذ أمر تصميم واحد في Figma يجمع شاشات desktop/mobile وحالات الاستخدام.
3. استدعاء سياق التصميم وصوره، وربط الألوان والتباعد والمكونات بكود React الحالي.
4. تطبيق الهوية العامة ثم إعادة بناء الدخول والنتائج، وتحديث أغلفة لوحات التحكم والتنقل دون تغيير منطق البيانات.
5. تحسين الخفة: CSS بدلاً من مؤثرات الرسم المكلفة، احترام reduced-motion، تأجيل صفحات الأدوار، وعدم إضافة مكتبات.
6. تشغيل lint/build وفحص الدخول بالحاسوب والهاتف، وتوثيق حدود فحص الشاشات التي تحتاج حساباً مأذوناً.

## مراجعة الاتجاه
استُبعدت التدرجات المتعددة والظلال الثقيلة والبطاقات المتطابقة. اللون الأزرق امتداد لهوية المنتج، والتكوين المداري يقتصر على الدخول. لا توجد أرقام أو أسماء حقيقية ضمن أمثلة Figma.

## الاسترجاع والدمج
- استُرجع سياق الشاشات الثماني وصورها قبل الدمج: الدخول `2:179` و`2:219`، الإدارة `2:245`، المديرة `2:305`، الموظفة `2:352`، الترتيب `2:379`، الحساب `2:409`، الحالات `2:431`.
- مكونات SDS المرجعية لا تملك تطبيقاً مثبتاً في المستودع؛ كُيّفت الحقول والأزرار الحالية دون إضافة مكتبة.
- وُحّدت الألوان والخط والعلامة والتنقل، وأعيد بناء الدخول وبطاقات النتائج مع الاحتفاظ ببياناتها الفعلية.
- مرجع Figma ذو الأمر الواحد يحتوي بعض ارتفاعات ثابتة وقصّ للنصوص والمجموعات؛ عالجت النسخة المدمجة ذلك بتدفق CSS طبيعي، دون أمر تصميم إضافي.
- تحميل لوحة الترتيب وصفحات الأدوار مؤجل حتى فتحها. لم تتغير الاعتماديات أو سياسات الصلاحيات.
- حُذف الفرع المحلي والبعيد `supabase-migration`. العمل الحالي على `codex/supabase-production`.

## التحقق
- نجح TypeScript وVite build.
- lint بلا أخطاء، مع تحذيرين سابقين only-export-components في AuthContext وDataContext.
- راجعت الدخول بصرياً في Chrome بعرض واسع وضيق، ووحدة التحكم خالية من أخطاء التشغيل أثناء الفحص.
- لم يُنفذ تسجيل دخول أو فحص بيانات الموظفات. فحص بقية الأدوار تفاعلياً يتطلب حساب اختبار مأذوناً.
- تغييرات التطبيق محلية ولم تُنشر على GitHub أو الاستضافة.
